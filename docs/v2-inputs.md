# V2 inputs — verbatim source lists

Converted from `weave_changes.odt` so the lists are diffable, greppable and reviewable in git.
**Wording is preserved exactly as written, typos included** — this is an input document, not a
specification. Where an item was ambiguous, the resolution lives in the guide or decision that
consumed it, not here.

How these are being used:

- The security and feature lists become **policy packs**: each item is a requirement the agent
  is told to build plus a check Weave runs. Check kinds are automatic, model-judged,
  conditional (only when the app has auth or payments) or human-only.
- The preset list became `design-guide/styles.json` — 93 raw entries reconciled into 90 styles.
  See that file for the merges and splits.
- The UI/UX laws are mostly model-judged, with a measurable subset (target size, response under
  400ms, navigation item counts).
- Item 80 of the feature list is a working rule for this repo, not a product feature: keep a
  current file, phase the implementation plan, and move superseded content to past-info.
